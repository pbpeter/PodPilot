Description

In a Kubernetes environment, you should never hardcode or directly provide sensitive data like database passwords and API keys. Kubernetes provides the Secret object to securely store and manage such information. Here's what the Secret definition looks like:

apiVersion: v1
kind: Secret
metadata:
  name: my-secret-key
  namespace: default
  labels:
    app: my-app
type: Opaque
data: # this must be base64 encoded. 
  secret-key: ZGV2LWRqYW5n

Similarly, you can best manage non-sensitive configuration data, like NGINX configuration files, using ConfigMaps. Both allow you to decouple configuration from your application images, making your deployments more flexible and secure.

For this project, we need both. First, let's create a Secret to securely manage our PostgreSQL database credentials. We'll define the Secret in a file, postgres-secret.yaml in the task_manager/k8s/secrets directory. Ensure to give the Secret a meaningful name, like postgres-secrets, because we'll reference it later. For this secret, use the stringData type, so you don't need to encode values manually. Use the following values:

  • database: task_manager

  • username: hyper

  • password: hyper_user2025

Next, your Django application requires a SECRET_KEY for cryptographic signing. Let's create another Secret named django-secret-key for this, which will contain the secret-key. You can save this in a file, django-secret.yaml in the task_manager/k8s/secrets directory as well. For this secret, use the standard data field, which requires the value to be base64 encoded. You can encode values from your terminal as follows:

# Bash
echo -n 'your-value' | base64

# PowerShell
[Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes("your-value"))

To serve static assets (images, JavaScript, and CSS files) for our application, we'll use an NGINX sidecar container (more on this later). To configure this container, we'll use a ConfigMap named task-manager-nginx-config to store its configuration. This allows you to update the NGINX configuration without rebuilding your Docker image.

You can find the ConfigMap in a file named nginx-configmap.yaml in the task_manager/k8s/base directory. All you need to do is apply it, as well as the two secrets, with the kubectl apply command.

Finally, verify that your secrets and configmap have been created successfully in the podpilot namespace using the following commands:

kubectl get secrets -n podpilot
kubectl get configmaps -n podpilot
Objectives

Here are the resources you need to create:

  • A Secret named postgres-secrets for PostgreSQL credentials.

  • A Secret named django-secret-key for the Django application's secret key.

  • A ConfigMap named task-manager-nginx-config for the NGINX sidecar container.
