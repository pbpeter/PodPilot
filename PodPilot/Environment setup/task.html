Description

Kubernetes is the standard way of deploying scalable, production-ready applications. But before we deploy to a production-ready cluster, let's create a reliable local environment for testing. Since you'll be building the application image, you need to install Docker. Next, you need to run a local Kubernetes cluster using kind or minikube. If you have Docker Desktop installed, you can also run a single- or multi-node Kubernetes cluster with kind or kubeadm directly from the interface.

Once you install it, verify with:

kubectl get nodes

Ensure you have kubectl installed before running the above command.

Next, let's create a namespace, podpilot, where all our resources will live. You can do it with:

kubectl create namespace podpilot

# or 
# kubectl create ns podpilot

Finally, we need to set the proper context and default namespace. This is especially useful if you have more than one cluster running, and also to make sure resources end up in the right namespace. You can check your available contexts with:

kubectl config get-contexts
kubectl config current-context
kubectl config view

Use the following commands to set the context and namespace:

kubectl config set-context <context-name> --namespace=podpilot
Objectives

This is what you need to do here:

  • Install and verify Docker.

  • Start a local Kubernetes cluster.

  • Configure kubectl.

  • Create a namespace, podpilot.

  • Set the proper context and namespace.
