Description

Kubernetes Pods are designed to be disposable, so any data written to a container's filesystem can be lost when the Pod restarts, gets rescheduled to another node, or is recreated during an update. To keep important state (like the Postgres data directory) across Pod lifecycles, Kubernetes provides StatefulSets.

But before we create one, let's create a headless Service so that other resources can connect to the database using a stable DNS name. Create a Service in a file named postgres-service.yaml (in task_manager/k8s/base). The Service should:

  • Use type: ClusterIP (default) since the database only needs to be accessible within the cluster.

  • Expose port 5432 (the standard PostgreSQL port).

  • Use a selector that matches the labels on your Postgres Pods (e.g., app: postgres).

  • Have a name that matches what you'll use as the database host in your application configuration (such as postgres) and as the serviceName for the StatefulSet.

  • Set ClusterIP: None so it is a headless Service.

Next, create a StatefulSet for the Postgres database in a file named postgres-statefulset.yaml (also in task_manager/k8s/base). It should:

  • Run a single Pod.

  • Configure environment variables for Postgres (name the variables as follows: POSTGRES_DB, POSTGRES_USER, and POSTGRES_PASSWORD) — you should reference these from your Postgres Secret using valueFrom.secretKeyRef.

  • Include the PGDATA variable set to /var/lib/postgresql/data/pgdata for storage. Setting it explicitly this way ensures stability and consistency.

  • Mount a persistent volume at /var/lib/postgresql/data.

  • Create a volumeClaimTemplate for 1Gi of storage in ReadWriteOnce mode.

  • Add basic resource requests/limits, plus readiness/liveness probes that verify Postgres is accepting connections.

Finally, create a migration Job in a file named migrate-job.yaml (in task_manager/k8s). A Job is ideal for database migrations because it runs a command to completion and stops. Configure it to run your Django image (task-manager:latest) and execute the migration command non-interactively (python manage.py migrate --noinput).

A job's manifest is similar to that of a Deployment.

Set the following needed environment variables (the application expects them to be named as shown):

  • DJANDO_SETTINGS_MODULE: (task_manager.production).

  • SECRET_KEY: (reference this from the django-secret Secret).

  • ALLOWED_HOSTS: "*"

  • Database connection settings:

    • Database engine (DB_ENGINE) set to django.db.backends.postgresql.

    • DB_NAME, DB_USER, DB_PASSWORD name/user/password pulled from the Postgres Secret using secretKeyRef.

      • For the DB_HOST and DB_PORT, point the app at your in-cluster Postgres endpoint (the Postgres Service name you used (postgres)) and port 5432.

  • Use .spec.template.spec.restartPolicy: OnFailure and set a reasonable .spec.backoffLimit like 3, so Kubernetes doesn't retry forever if something is misconfigured.

When you're done, you must apply the resources in order (Service → StatefulSet → Job), and verify that everything was created in the podpilot namespace. Useful checks include confirming the Service was created successfully, the Postgres Pod is running and ready, and the migration Job completed successfully.

You can also inspect logs for both the Postgres Pod and the Job to troubleshoot issues like missing Secret keys, incorrect DB hostnames, or permission problems on the mounted volume.

Here are some verification commands you can use:

kubectl get svc -n podpilot
kubectl get deploy -n podpilot
kubectl get pods -n podpilot
kubectl get jobs -n podpilot
kubectl get events -n podpilot
kubectl logs -n podpilot <job_pod_name>
Objectives

This is what you need to do here:

  • Create a headless Service for the StatefulSet.

  • Create a StatefulSet that mounts persistent storage and reads credentials from the Postgres Secret.

  • Create a migration Job that runs Django migrations.

Examples

Example 1: Referencing environment variables and secrets

env:
  - name: POSTGRES_USER
    valueFrom:
      secretKeyRef:
        name: <postgres-secret-name>
        key: <username-key>

Example 2: Migration command

command: ["python", "manage.py", "migrate", "--noinput"]

Example 3: Readiness/liveness probes

readinessProbe:
  exec:
    command:
    - pg_isready
    - -U
    - $(POSTGRES_USER)
  initialDelaySeconds: 10
  periodSeconds: 5
  timeoutSeconds: 3
  failureThreshold: 3
