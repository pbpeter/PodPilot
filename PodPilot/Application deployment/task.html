Description

In this last stage, we'll run our application in a Deployment so it can be replicated, updated safely, and automatically restarted when containers fail. To make the app reachable, we'll also create a Service for a stable in-cluster DNS name and load-balance traffic across the Pods.

First, we'll deploy the Service resource in task_manager/k8s/base/service.yaml. This Service exposes the application inside the cluster:

  • type: ClusterIP

  • name: task-manager

  • The selector must match the label on your application's pods (in this case, app: task-manager)

  • Expose port 80 and forward it (targetPort) to the Nginx container port, named http or numeric port 80

Next, create the Deployment in task_manager/k8s/base/deployment.yaml. The high-level layout of this deployment should be as follows:

  • An initContainer that runs once before the main containers start. It runs python manage.py collectstatic --noinput. This collects all static assets and writes them to a shared directory.

  • Django container: runs two replicas of the web app and listens on port 8000.

  • Nginx container (sidecar): listens on port 80, serves static files, and forwards dynamic requests to Django. It is also an initContainer with an appropriate restartPolicy to make it a sidecar.

Running nginx as a sidecar ensures that both nginx and the main container are on the same network. This allows Nginx to reach our Django server via localhost:8000. They also share the same volumes (so both can access the same static files). This allows the sidecar to add capabilities (static serving, proxying, logging, TLS termination, etc.) without changing the main app container.

Here are more details about the Deployment:

Init container

  • Name: collectstatic

  • Image: task-manager:latest

  • imagePullPolicy: IfNotPresent or Never (The image is guaranteed to be available in the node's cache because you loaded it earlier. Also prevents attempting to pull the image from the registry.)

  • Command: ["python", "manage.py", "collectstatic", "--noinput"]

  • Must set the environment variables required to run Django management commands, similar to how we set up the migration Job:

  • DJANGO_SETTINGS_MODULE = task_manager.production

  • STATIC_ROOT = /app/staticfiles

  • ALLOWED_HOSTS = *

  • SECRET_KEY read from a Kubernetes Secret via valueFrom.secretKeyRef

  • Mount a shared volume at /app/staticfiles

Nginx container (sidecar)

  • Name: nginx

  • Image: nginx:latest

  • containerPort 80 with name http

  • restartPolicy set to Always for a sidecar.

  • Mount:

    • shared static volume, static-files, read-only at /usr/share/nginx/html/static

    • an Nginx config read-only volume, nginx-config, at /etc/nginx/conf.d

  • Add resource requests/limits (keep modest)

  • Probes:

    • readinessProbe: HTTP GET /ready on port 80

    • livenessProbe: HTTP GET /health on port 80

Django container

  • Name: task-manager

  • Image: task-manager:latest

  • Ports: containerPort 8000 (give it the name django as configured in the ConfigMap and TCP protocol)

  • imagePullPolicy: IfNotPresent or Never (The image is guaranteed to be available in the node's cache because you loaded it earlier.)

  • Environment variables:

    • DJANGO_SETTINGS_MODULE = task_manager.production

    • SECRET_KEY from the Django Secret

    • ALLOWED_HOSTS = "*"

    • DB settings:

      • DB_ENGINE = django.db.backends.postgresql

      • DB_NAME, DB_USER, DB_PASSWORD from the Postgres Secret

      • DB_HOST = postgres (the Postgres Service name)

      • DB_PORT = "5432"

    • STATIC_ROOT = /app/staticfiles

  • Mount the shared static volume, static-files at /app/staticfiles

  • Add resource requests/limits (keep modest)

  • Add probes:

    • readinessProbe: HTTP GET /ready on port 8000

    • livenessProbe: HTTP GET /healthy on port 8000

For volumes, you need to set the following:

  • static-files: emptyDir: {} (shared within the Pod)

  • nginx-config: configMap volume pointing to the ConfigMap that contains your Nginx config (created earlier), so Nginx knows how to proxy to localhost:8000 and serve /static/.

Apply the manifests and verify rollout:

  • Service exists

  • Deployment has two replicas, Pods are ready

  • Endpoints are created for the Service

  • Logs show collectstatic completed, and both containers are healthy.

Verification and troubleshooting commands:

kubectl get svc -n podpilot
kubectl get deploy -n podpilot
kubectl get po -n podpilot
kubectl get endpointslices -n podpilot
kubectl get events
kubectl logs -n podpilot <pod_name> --all-containers
kubectl logs -n podpilot <pod_name> -c collectstatic # get logs for collectstatic container

Finally, port-forward the service mapping ports 8080:80 so that the application is accessible at localhost:8080. You're ready to begin using the application.

Bonus

To access Django's admin dashboard at localhost:8080/admin, begin by creating an admin user with the following command:

kubectl exec -it -n podpilot task-manager-6586f7f874-fhs5v -- python manage.py createsuperuser

kubectl exec -it allows you to execute interactive shell commands inside a running pod. The -i flag keeps stdin open, while -t allocates a pseudo-TTY—together, they enable a fully interactive terminal session.

In this example, task-manager-6586f7f874-fhs5v is one of the Pods in our Deployment. Replace it with a Pod in your instances. kubectl exec is particularly useful for:

  • Inspecting logs, checking environment variables, or debugging application issues directly inside the container

  • Running one-off commands or scripts without redeploying

  • Verifying configurations, installed packages, or file permissions

In our example, we're using it to create a super user that you can use to log in to Django's admin dashboard. Here are all the available endpoints:

  • /api

  • /api/tasks

  • /admin

  • /health

  • /ready

Objectives

This is what you need to do here:

  • Create a Service named task-manager that exposes port 80 internally and routes to the Nginx container's port.

  • Create a Deployment named task-manager with two replicas.

  • Use an init container to run collectstatic into a shared emptyDir volume.

  • Run Nginx on port 80 in the same Pod (sidecar pattern). In this case, it is expected to be run as a special init container.

  • Run Django on port 8000.

  • Read sensitive values (Django secret key and Postgres credentials) from Kubernetes Secrets via secretKeyRef.

  • Add resource requests/limits and readiness/liveness probes for both Django and Nginx.

  • Port-forward the task-manager service and verify the app is available at localhost:8080.

  • As a bonus, create a superuser and use the credentials to log in to Django's admin dashboard.

Examples

Example 1: Nginx volume mounts

volumeMounts:
  - name: static-files
    mountPath: /usr/share/nginx/html/static
    readOnly: true
  - name: nginx-config
    mountPath: /etc/nginx/conf.d
    readOnly: true

Example 2: Volumes


volumes:
  - name: static-files
    emptyDir: {}
  - name: nginx-config
    configMap:
      name: task-manager-nginx-config
